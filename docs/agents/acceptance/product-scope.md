# 产品范围与端到端验收

本文定义 Seamark 作为产品必须保持的边界和关键用户旅程。领域细节由其他验收文档约束。

## 1. 产品定位

Seamark 是面向小规模自有 Linux 服务器的单管理员运维控制面：Panel 在本地保存控制面数据，通过 SSH 完成接入和维护，通过 mTLS panel-agent 与 Docker Engine API 管理容器工作负载，并把服务器、资源、应用、DNS、证书、任务和诊断集中在一个 Web 界面。

- `PROD-SCOPE-001`：当前身份模型是一个固定管理员账户，不得在没有完整租户隔离、资源所有权和权限验收设计时局部引入多用户/RBAC。
- `PROD-SCOPE-002`：当前持久化以 Panel 本地 SQLite 四库和 dataRoot 文件为事实来源；浏览器缓存、Agent 本地状态和内存队列不得成为唯一控制面事实源。
- `PROD-SCOPE-003`：远端服务器当前只支持 Debian 12/13 与 Ubuntu 20.04、22.04、24.04、24.10、25.04、25.10、26.04；未支持发行版可以探测并明确拒绝依赖 APT/systemd 的写操作，不得误报支持。
- `PROD-SCOPE-004`：SSH 凭据支持密码和私钥；需要特权的动作必须在执行前验证 root 或免密 sudo 能力，不能把失败推迟到产生部分副作用之后。
- `PROD-SCOPE-005`：容器应用运行时要求兼容 panel-agent 和可用 Docker host；依赖缺失时仍允许查看 Panel 中已有配置和历史记录，但写操作必须明确阻止或排队为可诊断失败。
- `PROD-SCOPE-006`：项目处于 alpha 阶段不意味着可以破坏存量数据、安全门或用户可见语义；每次数据库与远端行为变更仍需迁移和失败恢复。

## 2. 全局产品不变量

- `PROD-INV-001`：任何页面刷新、浏览器重开或 Panel 重启后，已确认成功的配置仍可读取；仍在进行的异步工作恢复为真实状态，不能凭前端内存显示成功。
- `PROD-INV-002`：列表、详情、任务、事件和概览对同一资源状态使用同一语义；允许采样延迟，但必须显示更新时间或进行中状态，不得互相矛盾而无解释。
- `PROD-INV-003`：读操作不得隐式执行远端写入、部署、升级、删除、续签或密钥轮换；自动维护必须由明确设置的调度策略触发并可追踪。
- `PROD-INV-004`：危险操作的确认文本必须指出资源和影响范围；后端必须再次校验实际范围，不能信任前端展示值。
- `PROD-INV-005`：批量操作按每个目标保存结果；部分失败不得把整批显示为全成功，也不得丢失已成功目标的证据。
- `PROD-INV-006`：外部依赖不可用时优先保留既有安全配置与最后成功观测；不得用空响应覆盖有效缓存或删除远端资源。
- `PROD-INV-007`：所有秘密默认不回显，导出是显式、短时、可审计的例外；下载链接或 export ID 不得成为永久秘密访问能力。
- `PROD-INV-008`：应用和设施应用创建的远端资源必须带可验证托管身份；Panel 只能自动覆盖或删除身份匹配的资源。
- `PROD-INV-009`：语言、时区显示、主题或响应式布局变化不得改变业务请求、资源 ID、数值精度和时间筛选边界。
- `PROD-INV-010`：页面不支持的服务端能力不得通过隐藏按钮替代权限；服务端 API 始终实施完整验证和安全边界。

## 3. 首次使用旅程

### PROD-JOURNEY-001 首次登录与改密

- **前置**：全新数据目录，以默认管理员材料启动。
- **操作**：访问登录页，以初始凭据登录并提交新密码。
- **验收**：登录明确要求改密；改密前无法访问普通业务页面/API；成功后旧 token 与初始密码失效，重启后新凭据继续有效，并进入原始目标页或概览。
- **失败边界**：弱密码、错误当前密码、并发重复提交均不产生部分账号更新；限流不会泄露账号是否存在。

### PROD-JOURNEY-002 添加凭据和服务器

- **前置**：已改密管理员，有一台受支持或不受支持的可测试主机。
- **操作**：创建 SSH 凭据，探测主机，确认 host key，保存服务器并执行连接/系统信息检查。
- **验收**：秘密不回显；首次 host key 需要显式信任；支持系统展示系统/架构/权限能力，不支持系统明确限制写操作；失败不会保存虚假“在线/支持”状态。
- **失败边界**：网络超时、认证失败、host key 变化、无 sudo 和重复服务器分别可诊断，且不会覆盖原有可信 host key。

### PROD-JOURNEY-003 部署 Agent 与观察资源

- **前置**：服务器 SSH 与权限检查通过。
- **操作**：签发/重置 Agent 证书并部署 Agent，等待健康检查和资源报告。
- **验收**：目标架构收到正确二进制和独立 mTLS 材料；Panel 验证版本/身份；指标、Docker 资源与软件包观察带时间戳更新；Agent 离线时保留最后成功数据并显示离线。
- **失败边界**：部署中断可安全重试；证书轮换后旧证书按规定失效；不兼容版本不能执行破坏性请求。

## 4. 应用交付旅程

### PROD-JOURNEY-004 创建与验证应用

- **前置**：至少一个兼容且 Docker 可用的目标服务器。
- **操作**：开始编辑会话，填写 AppSpec/文件/挂载/端口/目标/反向代理，执行验证和预览，再提交。
- **验收**：会话隔离未提交修改；验证返回全部结构化问题；预览明确各服务器变化；提交原子创建不可变 revision、目标实例和协调工作，刷新页面可继续追踪。
- **失败边界**：版本冲突、非法路径、缺失变量、无效证书或目标能力不足不得产生半个应用或泄漏临时上传。

### PROD-JOURNEY-005 部署、观察与操作

- **前置**：应用已保存且目标可达。
- **操作**：部署/启用、查看运行态和日志、重启、停止、检查/更新镜像、修改后再次部署。
- **验收**：每次动作有 intent/operation/task 或 Job 证据；同一目标串行收敛到最新 generation；日志按选定实例获取；停止不删除数据，删除等待所有托管目标清理完成。
- **失败边界**：超时后可幂等重放；旧执行不能覆盖新停止/删除目标；同名非托管资源仅报告冲突，绝不覆盖。

### PROD-JOURNEY-006 入口网关、DNS 与证书

- **前置**：应用暴露服务，有 Cloudflare 域名或可用自签名 CA。
- **操作**：同步域名/记录，签发或导入证书，在应用路由选择证书并协调入口网关。
- **验收**：provider token 不回显；DNS 缓存与刷新时间可见；ACME 通过任务显示进度；证书引用、SAN/有效期和私钥匹配通过校验后才进入网关；更新证书会触发受影响配置协调。
- **失败边界**：传播超时、挑战清理失败、被引用资产删除、证书不匹配和入口网关不可用均保持旧可用配置并给出可重试证据。

## 5. 日常维护与恢复旅程

### PROD-JOURNEY-007 批量维护

- **前置**：多台在线/离线服务器具有不同能力。
- **操作**：刷新并升级软件包、刷新/清理/升级镜像、管理防火墙或重启服务器。
- **验收**：选择范围在提交前可见；每台服务器独立记录步骤与结果；离线或不支持目标不拖成全局伪成功；重复触发遵循资源互斥策略。
- **失败边界**：部分成功如实聚合；远端命令超时后不得猜测成功；危险清理只作用于明确未使用且非受保护资源。

### PROD-JOURNEY-008 备份、维护态与恢复

- **前置**：Panel 有真实四库、秘密与文件数据。
- **操作**：导出加密备份，下载并退出维护态；上传备份预检，确认重启恢复；处理需要密码、失败或 pending 状态。
- **验收**：备份清单完整并有完整性校验；维护 token 与普通 token 隔离；恢复先预检后原子替换，成功启动后读取恢复数据；原数据在最终提交前可回滚。
- **失败边界**：错误密码、篡改/截断、版本或路径不兼容、磁盘不足和进程重启都不会留下混合的新旧数据；失败页面可诊断并提供安全重试/清除入口。

## 6. 明确不应隐式扩展的范围

- `PROD-NONGOAL-001`：没有持久化依赖/补偿状态机时，不支持把应用 move 实现为互不关联的“目标部署 + 源删除”；必须明确拒绝或先完成设计。
- `PROD-NONGOAL-002`：不得假设公网、Cloudflare、GitHub 或镜像仓库永远可用；除用户请求的具体操作外，外部检查失败不应阻止本地配置读取和 Panel 启动。
- `PROD-NONGOAL-003`：不得通过 SSH shell 命令重新实现已有 Agent Docker API 写操作；远端职责切换必须有完整兼容与安全验收设计。
- `PROD-NONGOAL-004`：不得把开发模式专用页面、Mock API 或 pprof 暴露策略自动提升为生产用户功能。
