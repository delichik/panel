# v3 交互模型规范

> 六条交互原则是所有页面必须遵守的底线。它们是**约束**，不是页面交互的答案——每个页面的信息层级、操作流、表单组织必须从该页面的用户任务重新设计，严禁照搬 v1 / v2 归档页面的操作顺序与分区方式。

## 1. 操作分级

部署与设施诊断须明确错误对象、原因与下一步；容器状态、部署结果和请求日志样本不得混称健康。原诊断/失败运行日志用折叠且内部滚动区域展示，按需检查无后台轮询，并丢弃配置变化后的迟到响应。

**做法**

- 每个作用域（页面、详情区、对话框、表格行）至多一个主操作（primary 按钮）。
- 危险操作（删除、停用、重置）使用 `error` 语义，不与主操作并列展示，且必须经确认对话框。
- 批量操作栏只在存在选中项时出现，无选中即消失。
- 对象级操作放在对象所在表格的行操作区；页面级主操作放 PageHeader actions；常用操作直接平铺可见，只有低频/危险操作收进更多菜单；需要参数面板或逐文件/逐节点上下文的操作保留在覆盖详情内。

**反例**

- 一页面上多个 primary 按钮争抢视线。
- 删除按钮与保存按钮并排同色展示。
- 无选中项时批量栏占位常驻。
- 把某台服务器的"重启 Agent"放进全局页头，形成"未绑定当前资源"的误导。

## 2. 列表查询进 URL

**做法**

- 搜索、筛选、排序、分页状态同步进 URL query；返回页面或刷新时从 URL 恢复。
- 列表必须区分四种空态：**无数据**（引导创建）、**筛选为空**（提示调整条件）、**加载失败**（错误 + 重试）、**无权限**（说明而非报错）。
- 分页固定在模板底部（ListPage `pagination` 插槽），不随表格滚动。

**反例**

- 筛选状态只存在组件内存，后退即丢失。
- 四种空态混用一句"暂无数据"。
- 把查询参数编码进 localStorage 而非 URL，导致链接不可分享。

## 3. 编辑脏状态与离开保护

**做法**

- 表单有未保存修改时脏状态可见（EditorPage footer 显示脏提示，提交按钮随之启用）。
- 离开未保存页面（路由跳转、关闭浏览器）弹确认；路由级离开守卫由业务页面配置。
- 本地校验错误就近显示在字段旁；服务端校验错误摘要置顶于提交栏（footer），并可定位到字段。
- 提交期间锁定表单，禁止重复提交。

**反例**

- 修改后静默允许离开，数据丢失。
- 服务端校验失败只在顶部弹一条 snackbar，用户找不到出错字段。
- 提交中按钮仍可点击导致重复创建。

## 4. 异步操作两阶段

**做法**

- 区分"请求已接受"（任务已创建/已提交协调）与"执行完成"（任务成功/失败）。按钮反馈只承诺前者。
- 创建后台 execution 后提供追踪入口（跳转 `/executions` 详情或就地卡片）。
- Execution 状态可恢复：刷新页面后仍能经服务器详情 Agent 卡片或 `/executions` 看到进行中 run；轮询/SSE 沿用现有机制（`/events` 与 `/logs` 不自动轮询）。
- 长时间运行操作给出进行中指示，UI 不假死。
- 创建任务前的规划/校验失败必须在资源详情保留结构化原因与活动入口，提交失败后重载诊断，不能只依赖短暂 Toast；没有执行就不伪造任务。
- 部署 remote-fence monitor 且尚无 Agent 步骤进度时，使用独立警告状态（系统核实中），不得推断成功/失败，也不得要求用户声明成败；一旦投影出真实阶段（拉取/创建/启动/验证）则按普通部署进度展示。部署操作状态与实际实例运行状态分别呈现；当前故障恢复后清除告警，历史失败仍可查询。
- 维护清理等后台操作必须在进入页面时查询当前状态、离页后可恢复阶段与时间；网络异常只表示请求/结果未确认，重试状态查询不得重发写请求。部分删除失败说明已有批次无法回滚；逻辑清理完成与后台恢复成功分别判断。页面卸载停止本页轮询，服务端已接受工作继续执行。

**反例**

- "保存并应用"的成功提示暗示部署已完成。
- 提交后无任何任务入口，用户只能干等或反复操作。
- 刷新页面后进行中任务从界面上"消失"。

## 5. 反馈分层

**做法**

- 全局反馈只有三种渠道，按“谁触发、是否阻塞用户”互斥选择，不得混用：
  1. **事件通知 / 成功提示（右上角 toast）**：只承载后端过程事件的开始/成功/失败通知（经内存通知通道长轮询，见 `UI-SHELL-065`、`ENG-EVT-011`）与用户显式操作的**成功**提示（保存成功、已复制、任务已提交/请求已接受）。HTTP 请求（`module=http`）永不成为事件通知，请求日志统一 `debug`（`ENG-LOG-009`）。
  2. **全局错误 Dialog**：只承载“用户当前阻塞操作”的失败——保存/提交/创建/更新、删除、确认类动作、测试连接、重启/部署/停止、证书签发/续签/导入/导出、显式导入导出与清理、登录/改密、外观保存/上传/移除/恢复默认、语言持久化等由用户显式点击或提交触发的动作，以及阻塞性冲突/被阻止（记录冲突、引用占用、apply 失败、网关移除被阻止、配置校验阻止提交等）。Dialog 含标题、可选说明与「查看日志」深链（关联本次请求）、关闭按钮；一次只呈现一个，队列有上限，复用 Dialog 的焦点/滚动锁/Escape 语义。自动/后台任务的结果以事件通知为准，不弹错误 Dialog。
  3. **就地状态**：页面/区块首次加载失败、手动刷新失败、后台自动刷新失败、自动保存失败只在失败作用域显示错误空态、陈旧标记或 `AutoSaveStatus` error 与重试入口；有旧数据时保留旧数据——关键页面（概览/诊断/DNS 记录等）就地标记陈旧，普通列表刷新失败允许静默保留旧快照；不弹窗、不 toast。
- Toast 视觉与行为（不透明 `--panel-popover`、语义只靠边框与图标、可见堆叠上限、悬停/焦点暂停并按剩余时间继续、卸载清理计时器、桌面位于 56px 顶栏之下）保持不变；事件通知按事件状态映射 tone，并提供「查看日志」深链。
- **结构化错误就地展示**：表单校验在字段旁与提交栏摘要；配置诊断在对应面板；阻塞性冲突/被阻止（记录冲突、引用占用、apply 失败等）属于用户显式动作失败，走全局错误 Dialog；高风险覆盖用确认对话框而不是错误 Dialog。
- 状态用语义色表达（success/warning/danger/info），经 Panel 自有 Badge、Alert 或 token 获得，不与品牌色混用。

**反例**

- 把加载失败、自动刷新失败或自动保存失败做成 danger toast 或错误 Dialog。
- 把字段校验或结构化诊断做成错误 Dialog；把字段校验错误送进右上角 toast。
- 在右上角显示 HTTP 请求日志、请求异常或后端自由错误文本。
- 用 toast 承载唯一的多行服务端错误详情，几秒后消失无处可查。
- 事件通知的失败状态同时再弹一个错误 Dialog，造成双重反馈；或把事件通知的失败当作页面加载失败。
- 用 error 红做普通强调、用 primary 蓝表达"成功"。

## 6. 加载骨架屏

**做法**

- 整页首次加载用自有 Skeleton，按页面结构铺设，不用裸 spinner 居中。
- 局部加载（切换选中对象、刷新单个区块）保留在当前区域内：显示该区域骨架或 loading，**不影响页面其余部分**。
- 已有内容后的刷新保留原内容 + 局部 loading 指示，不清空重闪。
- 切换上下文（换服务器、换对象）立即清空旧数据并显示加载态，忽略迟到响应；覆盖式详情打开时按选中对象 key 播放一次进场（`TableDetailLayout` 的 `detail-swap`），同一对象的刷新不重播；关闭详情不播放拖沓退场并保留列表滚动位置。
- 文本区域、对话框正文和卡片等需要等待接口响应的位置统一使用 `LoadingOverlay`；任何网络请求等待都必须在对应作用域内给出加载反馈，不允许只显示文字或无反馈。
- 数据列表在骨架/加载态就绪后统一以进场动效填充内容：列表容器加 `motion-stagger`、行/卡片加 `motion-reveal`（表格行用 `motion-table-row`、可交互项用 `motion-list-item`），效果与系统事件列表一致；仅首屏/新增项播放，已有内容刷新不重放。

**反例**

- 每次刷新都整页白屏 + 居中 spinner。
- 切换选中对象期间仍展示上一对象的数据。
- 局部刷新导致整页布局跳动。

## 附：对话框与菜单

- 确认对话框用于不可逆/危险操作，说明影响范围；普通编辑用标准对话框承载完整字段表单，页面正文只展示摘要。
- 溢出菜单承载次要/危险操作；Tooltip 用于解释图标按钮与截断文本，不承载关键信息。
- 对话框、菜单、消息等浮层视觉由主题 token 统一（见 [visual-tokens.md](visual-tokens.md)），页面不自造浮层样式。
- 全局错误 Dialog 复用标准 Dialog 语义（固定 header/footer、焦点圈定、Escape 关闭、滚动锁），由应用外壳统一挂载；它只承载用户当前阻塞操作的失败，不承载加载/自动刷新失败，并可按本次请求关联提供「查看日志」。
- 对话框采用固定 header/footer 与唯一可滚动 body，打开后移动焦点、圈定 Tab、支持 Escape 关闭并恢复触发点焦点；不因点击遮罩关闭，只能通过关闭按钮、取消操作或 Escape 关闭。打开期间锁定背景滚动；嵌套浮层用引用计数，最后一个关闭时才恢复。
- 多个浮层同时打开时只有最上层响应文档级 Escape 与焦点模型，下层不得被连带关闭；焦点意外离开面板时最上层仍须可 Escape 关闭（`useOverlayBehavior` 的文档级兜底）。
- 对话框、菜单、抽屉、Toast 的进入与退出动画成对实现（`dialog-*` / `menu-*` / `drawer-*` / `toast-stack-*`，见 [visual-tokens.md](visual-tokens.md)），动画不得改变焦点时序与键盘模型。
- 对话框与移动端侧边抽屉共享 `web/src/composables/useOverlayBehavior.ts` 的焦点圈定、Escape 关闭与焦点恢复逻辑；抽屉另以 dialog 语义呈现并锁定背景滚动。覆盖式详情复用同一 composable 的 Escape 栈与焦点归还，但不锁背景滚动、不做对话框语义。
- Select 等可能出现在滚动容器中的浮层传送至顶层并按触发控件定位，避免被容器裁切；Select 必须把页面传入的 `aria-label`/`aria-invalid` 落到 combobox 控件上。
- `menu` / `tablist` 等 ARIA 角色必须同步实现对应方向键、Home/End、Escape（适用时）与焦点模型；Dropdown 在 Tab 离开时必须关闭并同步 `aria-expanded`，不得留下“已展开”的假状态；Tabs 在中窄屏允许标签栏横向滚动。
