# v3 交互模型规范

> 六条交互原则是所有页面必须遵守的底线。它们是**约束**，不是页面交互的答案——每个页面的信息层级、操作流、表单组织必须从该页面的用户任务重新设计，严禁照搬 v1 / v2 归档页面的操作顺序与分区方式。

## 1. 操作分级

**做法**

- 每个作用域（页面、详情区、对话框、表格行）至多一个主操作（primary 按钮）。
- 危险操作（删除、停用、重置）使用 `error` 语义，不与主操作并列展示，且必须经确认对话框。
- 批量操作栏只在存在选中项时出现，无选中即消失。
- 对象级操作放在对象所在的详情区/行尾；页面级主操作放 PageHeader actions；次要操作收进更多菜单。

**反例**

- 一页面上多个 primary 按钮争抢视线。
- 删除按钮与保存按钮并排同色展示。
- 无选中项时批量栏占位常驻。
- 把某台服务器的"重启 Agent"放进全局页头，形成"未绑定当前资源"的误导。

## 2. 列表查询进 URL

**做法**

- 搜索、筛选、排序、分页状态同步进 URL query；返回页面或刷新时从 URL 恢复。
- 列表必须区分四种空态：**无数据**（引导创建）、**筛选为空**（提示调整条件）、**加载失败**（错误 + 重试）、**无权限**（说明而非报错）。
- 分页固定在模板底部（ListPage `pagination` 插槽），不随表格滚动。

**反例**

- 筛选状态只存在组件内存，后退即丢失。
- 四种空态混用一句"暂无数据"。
- 把查询参数编码进 localStorage 而非 URL，导致链接不可分享。

## 3. 编辑脏状态与离开保护

**做法**

- 表单有未保存修改时脏状态可见（EditorPage footer 显示脏提示，提交按钮随之启用）。
- 离开未保存页面（路由跳转、关闭浏览器）弹确认；路由级离开守卫由业务页面配置。
- 本地校验错误就近显示在字段旁；服务端校验错误摘要置顶于提交栏（footer），并可定位到字段。
- 提交期间锁定表单，禁止重复提交。

**反例**

- 修改后静默允许离开，数据丢失。
- 服务端校验失败只在顶部弹一条 snackbar，用户找不到出错字段。
- 提交中按钮仍可点击导致重复创建。

## 4. 异步操作两阶段

**做法**

- 区分"请求已接受"（任务已创建/已提交协调）与"执行完成"（任务成功/失败）。按钮反馈只承诺前者。
- 创建后台任务后提供任务详情入口（跳转任务中心或任务详情）。
- 任务状态可恢复：刷新页面后仍能经任务中心看到进行中任务；轮询/SSE 沿用现有机制。
- 长时间运行操作给出进行中指示，UI 不假死。

**反例**

- "保存并应用"的成功提示暗示部署已完成。
- 提交后无任何任务入口，用户只能干等或反复操作。
- 刷新页面后进行中任务从界面上"消失"。

## 5. 反馈分层

**做法**

- Toast 承载**短暂成功与提示**以及所有**异常消息**：保存成功、已复制、任务已提交、API/操作异常统一在顶部 toast 展示。
- **结构化错误就地展示**：表单校验在字段旁与提交栏摘要；配置诊断在对应面板；需要用户决策的用对话框；区块加载失败保留重试入口，但异常详情走 toast。
- 状态用语义色表达（success/warning/danger/info），经 Panel 自有 Badge、Alert 或 token 获得，不与品牌色混用。

**反例**

- 用 snackbar 展示多行服务端错误详情，几秒后消失无处可查。
- 整页只弹全局错误条，具体哪个区块失败不明。
- 用 error 红做普通强调、用 primary 蓝表达"成功"。

## 6. 加载骨架屏

**做法**

- 整页首次加载用自有 Skeleton，按页面结构铺设，不用裸 spinner 居中。
- 局部加载（切换选中对象、刷新单个区块）保留在当前区域内：显示该区域骨架或 loading，**不影响页面其余部分**。
- 已有内容后的刷新保留原内容 + 局部 loading 指示，不清空重闪。
- 切换上下文（换服务器、换对象）立即清空旧数据并显示加载态，忽略迟到响应。
- 文本区域、对话框正文和卡片等需要等待接口响应的位置统一使用 `LoadingOverlay`；任何网络请求等待都必须在对应作用域内给出加载反馈，不允许只显示文字或无反馈。
- 数据列表在骨架/加载态就绪后统一以进场动效填充内容：列表容器加 `motion-stagger`、行/卡片加 `motion-reveal`（表格行用 `motion-table-row`、可交互项用 `motion-list-item`），效果与系统事件列表一致；仅首屏/新增项播放，已有内容刷新不重放。

**反例**

- 每次刷新都整页白屏 + 居中 spinner。
- 切换选中对象期间仍展示上一对象的数据。
- 局部刷新导致整页布局跳动。

## 附：对话框与菜单

- 确认对话框用于不可逆/危险操作，说明影响范围；普通编辑用标准对话框承载完整字段表单，页面正文只展示摘要。
- 溢出菜单承载次要/危险操作；Tooltip 用于解释图标按钮与截断文本，不承载关键信息。
- 对话框、菜单、消息等浮层视觉由主题 token 统一（见 [visual-tokens.md](visual-tokens.md)），页面不自造浮层样式。
- 对话框采用固定 header/footer 与唯一可滚动 body，打开后移动焦点、圈定 Tab、支持 Escape 关闭并恢复触发点焦点；不因点击遮罩关闭，只能通过关闭按钮、取消操作或 Escape 关闭。对话框、菜单、抽屉、Toast 的进入与退出动画成对实现（`dialog-*` / `menu-*` / `drawer-*` / `toast-stack-*`，见 [visual-tokens.md](visual-tokens.md)），动画不得改变焦点时序与键盘模型。
- 对话框与移动端侧边抽屉共享 `web/src/composables/useOverlayBehavior.ts` 的焦点圈定、Escape 关闭与焦点恢复逻辑；抽屉另以 dialog 语义呈现并锁定背景滚动。
- Select 等可能出现在滚动容器中的浮层传送至顶层并按触发控件定位，避免被容器裁切。
- `menu` / `tablist` 等 ARIA 角色必须同步实现对应方向键、Home/End、Escape（适用时）与焦点模型；Tabs 在中窄屏允许标签栏横向滚动。
