# 应用模板变量、Panel 托管文件与证书中心设计

## 目标

改善应用模板变量的可发现性和编辑体验，并允许应用直接挂载由 Panel 管理、会自动更新的文件。

本次改动包含：

- 在模板编辑区提供变量目录，并将变量插入当前光标位置。
- 将自定义变量从 JSON 文本改为可增删的键值表单。
- 提供按实际部署节点解析的服务器内置变量。
- 移除面向用户的 `files` 模板变量概念。
- 支持挂载 Panel 托管证书文件。
- 证书续期后刷新引用该证书的应用。
- 将证书管理提升为一级菜单，并统一管理 Nomad 内置证书、ACME 域名证书和自签证书。

## 命名规则

所有面向用户公开的模板变量 key 使用 `snake_case`，不使用驼峰命名。

服务器变量位于 `server` 命名空间：

- `server.id`
- `server.name`
- `server.ssh_host`
- `server.ssh_port`
- `server.ssh_username`

用户自定义变量继续位于 `vars` 命名空间，例如 `vars.image_tag`。

证书属性使用：

- `certificate_pem`
- `private_key_pem`
- `domains`

## 模板解析

模板分为两个阶段：

1. Panel 保存或部署应用时解析全局变量，包括 `vars.*` 和证书等不依赖实际落点的内置数据。
2. Nomad allocation 启动时解析节点变量，使同一应用在不同服务器上得到不同的 `server.*` 值。

Panel 托管的 Nomad 节点已经通过 `meta.panel_server_id` 关联服务器记录。节点加入、引导或重新部署时，将服务器配置中的非敏感属性同步到 Nomad node meta。模板目录返回可插入的节点变量表达式，用户不需要理解底层 Nomad 表达式。

SSH 地址取服务器配置中的 `host`，不是系统探测到的网卡地址。

## 变量目录与编辑器

应用 API 提供结构化变量目录。每个目录项至少包含：

- 稳定标识
- 分类
- 展示名称和说明所需的稳定翻译 key 或类型
- 可插入的模板表达式
- 解析阶段

编辑器在 YAML 规格和应用文本模板旁提供“插入变量”入口。用户选择变量后，表达式插入 textarea 当前选区；没有选区时插入当前光标位置，并恢复焦点。

自定义变量使用键值行编辑。保存时仍转换为现有的 `Record<string, string>`，不改变数据库结构。

变量目录不再展示 `files`。应用文件是部署资产，不是用户可复用的模板变量。

## Panel 托管文件

挂载类型新增 `panel_file`，与应用文件 `file` 分开。

Panel 文件目录首期提供已签发证书的两个文件：

- 证书链
- 私钥

挂载配置保存稳定引用，不保存证书当前文件系统绝对路径。引用包含资源类型、证书 ID 和文件种类。渲染 Nomad job 时，Panel 读取当前证书内容，通过 Nomad template 写入 allocation，再以只读 bind mount 挂入容器。

私钥不得通过变量目录直接展示内容，也不得出现在前端 API 响应中。前端只获得可选择的资源元数据。

## 证书续期联动

证书签发或续期成功后，查找引用该证书 Panel 文件的已启用应用并重新注册对应 Nomad job。Nomad template 内容变化后按照应用文件现有策略重启任务。

续期失败时保留原证书文件和现有应用，不触发空内容覆盖。

删除仍被应用引用的证书时返回冲突错误，并提示先移除相关挂载。

## 统一证书资源

证书中心使用统一资源标识描述以下类型：

- `nomad_builtin`：Panel 托管的 Nomad CA、agent 证书和 Panel client 证书。
- `acme`：通过 DNS-01 签发并自动续期的域名证书。
- `self_signed_ca`：可重复使用的自签 CA。
- `self_signed_leaf`：由指定自签 CA 签发的域名或 IP 证书。

统一资源层负责：

- 稳定 ID、名称、类型、状态、签发者、有效期和更新时间。
- Panel 文件目录暴露。
- 引用检查。
- 续签、重新生成和同步后的依赖刷新。

不同类型保留各自的生成和更新逻辑，避免把 Nomad TLS 轮换、ACME DNS challenge 与自签 X.509 签发混成一个流程。

## 证书引用保护

删除证书前必须统一检查引用：

- 应用的 `panel_file` 挂载。
- Nomad 反向代理域名匹配或显式证书引用。
- 其他系统配置中的稳定证书资源 ID。
- 自签 CA 与其签发的叶子证书关系。

存在引用时返回冲突错误，并返回可供界面展示的引用摘要。不能删除文件后再依赖运行时报错。

Nomad 内置证书不能删除。自签 CA 仍有子证书时不能删除。ACME 或自签叶子证书被任何位置使用时不能删除。

## Nomad 内置证书

证书一级菜单下提供“内置证书”二级页面，展示：

- Nomad CA。
- Nomad agent 证书。
- Panel Nomad client 证书。
- 有效期、指纹和更新时间。

内置证书只允许重新生成，不允许删除。重新生成会轮换 CA 和全部相关证书，并自动重部署全部 Panel 托管 Nomad 节点。

操作前必须显示高风险二次确认，明确提示：

- 全部 Nomad 节点将重新部署。
- 调度和应用可能短暂中断。
- 操作过程可在任务中心查看。

轮换任务必须先生成并验证新的本地资产，再按可恢复顺序同步 Nomad server、clients 和 Panel client 配置。失败时任务记录具体阶段和日志，不能把本地客户端留在无法连接任何 Nomad server 的状态。

## 域名证书

“域名证书”二级页面承接现有 ACME 证书能力，并增加：

- 立即续签。
- 自动续签状态和下次续签时间。
- 续签任务入口。
- 删除前统一引用检查。

签发或续签成功后自动同步：

- 使用该证书的应用 Panel 文件挂载。
- 使用该证书的 Nomad 反向代理配置。

续签失败继续保留上一份可用证书。

## 自签证书

“自签证书”二级页面同时管理 CA 和叶子证书。

自签 CA：

- 可创建多个。
- 可重复用于签发证书。
- 保存 CA 证书和私钥。
- 有子证书或其他引用时禁止删除。

自签叶子证书：

- 必须选择一个已有 CA。
- 支持 DNS 名称和 IP 地址 SAN。
- 生成证书、私钥和公钥。
- 支持重新签发并自动同步引用方。
- 被使用时禁止删除。

私钥内容不通过普通列表 API 返回，只能作为受控 Panel 文件使用。证书详情可展示公钥、指纹、SAN、签发者和有效期。

## 导航与页面

侧边栏新增一级菜单“证书”，包含三个二级菜单：

- 内置证书
- 域名证书
- 自签证书

原 DNS 下的证书入口迁移到“证书 / 域名证书”。旧 URL 保留重定向，避免已有书签失效。证书运行时默认设置可继续保留在设置页，但导航名称与证书中心职责保持清楚。

## 任务与同步

以下操作进入任务中心：

- Nomad 内置证书重新生成和全部节点重部署。
- ACME 签发与立即续签。
- 自签叶子证书重新签发。
- 证书更新后的应用和反向代理同步。

同一次证书更新及其多个依赖同步使用同一个 `operation_id`，便于任务中心聚合展示。同步失败不能回滚已经成功生成的证书，但必须记录未完成的引用方，允许用户重试同步。

## 兼容性

- 现有 `variables_json` 和自定义变量行为保持兼容。
- 现有 `file`、`volume`、`host`、`global`、`persistent` 挂载继续有效。
- 现有证书驼峰字段模板在 alpha 迁移期继续解析，但不再出现在变量目录；文档和新插入内容只使用蛇形字段。
- 数据库如需新增 Panel 文件挂载字段，必须提供旧数据库迁移；优先复用 appspec mount 的稳定字段，避免新增应用表列。
- 现有 `certificates` ACME 数据需要迁移或兼容映射到统一证书资源，不丢失证书路径、续签时间和变量名。
- 原 `/dns/certificates` 路由保留重定向。

## 错误处理

- 节点未关联 Panel 服务器时，使用节点模板变量的 allocation 应明确失败，不能静默写入空值。
- Panel 文件引用不存在、证书未签发或文件不可读时，应用校验或部署失败并指出具体挂载。
- 自定义变量 key 为空、重复或不符合模板标识规则时，前端阻止保存，后端继续做最终校验。
- Nomad 证书轮换未完成全部节点同步时，任务失败并保留可诊断状态；界面不得显示为完全成功。
- 自签证书 SAN 为空、CA 不存在、CA 私钥不可读或证书仍被引用时返回稳定错误码。

## 验证范围

- 后端测试覆盖变量目录、节点元数据生成、`panel_file` 校验和渲染、证书续期联动与引用删除保护。
- 后端测试覆盖自签 CA/叶子签发、SAN、CA 子证书删除保护、Nomad 轮换任务和旧数据库迁移。
- 前端测试覆盖自定义变量表单、变量光标插入、Panel 文件选择和保存结构。
- 前端测试覆盖证书一级菜单、三个二级路由、立即续签、危险确认和引用冲突展示。
- 按仓库规则通过 `task test:backend` 与 `task test:web` 执行相关验证；涉及构建或类型链路时补充对应 `task build:*`。
- 同步更新应用模块、证书模块、前端模块和国际化状态文档。
