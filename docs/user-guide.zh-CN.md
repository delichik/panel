# 使用 Panel

[English](user-guide.md) | 简体中文

本说明按照“从全新 Panel 到第一个正常运行的容器应用”组织，是面向任务的新用户指南，不是所有字段的完整参考手册。

如果 Panel 还没有运行，请先阅读[部署 Panel](deployment.zh-CN.md)。

## 先理解三个层次

- **Panel 主机：**运行 Panel 容器并保存 `panel-data` 数据卷的主机。
- **目标服务器：**登记到 Panel 中，由 Panel 通过 SSH 和 panel-agent 管理的 Debian 或 Ubuntu 服务器。
- **应用容器：**Panel 通过目标服务器上的 Docker Engine 创建的实际工作负载。

Panel 不需要把目标服务器的 Docker Socket 挂载到 Panel 容器。Panel 会在目标服务器安装 Agent，然后通过双向 TLS 主动连接该 Agent。

## 准备目标服务器

添加服务器前，请确认：

- 系统是项目 README 列出的 Debian 或 Ubuntu 版本。
- Panel 主机能够访问目标服务器的 SSH 地址和端口。
- SSH 账号是 `root`，或者具备免密 `sudo`。
- 部署容器应用前，目标服务器已经安装并运行 Docker。
- Agent 安装后，Panel 主机能够访问目标服务器的 `9786/tcp`。
- 目标服务器能够访问应用使用的容器镜像仓库。

条件允许时，应只允许 Panel 主机访问 `9786/tcp`。不需要通过 TCP 暴露目标服务器的 Docker Engine；默认 Docker Host 是本机 Unix Socket：`unix:///var/run/docker.sock`。

## 1. 首次登录

推荐先在 Panel 宿主机执行 `docker exec -it panel /app/panel setup`：该命令通过 SSH 将当前宿主机纳管、安装 Agent、登记唯一 Panel 宿主节点，并部署 Panel 自身的域名入口，完成后使用命令输出的 URL 登录。setup 只是便捷路径——也可以跳过它，在 **应用 → 设施应用** 的入口网关里启用 Panel 访问入口并选择服务器与域名；首次保存时，所选服务器会被登记为 Panel 宿主节点。

打开 Panel 地址，使用初始账号登录：

- 用户名：`admin`
- 密码：`admin`

Panel 会立即要求设置不同的新密码。修改密码时还会轮换 JWT 签名密钥，因此应先完成此步骤，再添加基础设施。

登录后，可以先检查以下设置：

- **设置 → 通用：**界面语言、Token 有效期、指标保留、采集间隔和远程命令超时。
- **设置 → 证书：**如果准备签发公网证书，请填写 ACME 邮箱并检查证书默认设置。
- **设置 → 安全：**管理员账号、密码和 JWT 密钥设置。

## 2. 添加 SSH 凭据

打开 **服务器 → 凭据**，选择 **新增凭据**。

Panel 支持：

- 用户名和密码。
- 用户名和私钥，可选私钥口令。

给凭据设置容易识别的名称，例如 `production-root` 或 `lab-sudo`。同一份凭据可以复用于多台服务器。

自动安装 Agent 和执行特权维护操作时，账号必须是 `root`，或者支持非交互式免密 `sudo`。需要交互输入 sudo 密码的账号无法自动完成这些操作。

## 3. 添加服务器

打开 **服务器 → 节点**，选择 **新增服务器**。

填写：

- 显示名称。
- IPv4 和/或 IPv6 地址（至少填写一个，必须是 IP 字面量）；连接地址由系统派生，IPv4 优先。
- SSH 端口。
- 上一步创建的凭据。
- 可选的 SSH 用户名覆盖值。
- Docker Host。除非目标服务器使用其他端点，否则保持 `unix:///var/run/docker.sock`。

保存服务器后，Panel 会启动首次初始化操作，检查 SSH、操作系统、CPU 架构和特权命令能力。如果首次初始化在服务器完成登记前失败，Panel 会删除未完成的服务器记录，让你修正连接信息后重新添加。

首次初始化成功且服务器具备所需权限后，Panel 会自动安排安装 panel-agent。

## 4. 确认 Agent 和 Docker 状态

打开新服务器的详情，等待初始化操作完成。部署应用前请确认：

- 服务器可以访问。
- 检测到的操作系统受支持。
- 特权模式为 root 或免密 sudo。
- Agent 状态为兼容。
- Docker 状态正常，并且报告的 Docker Host 与配置一致。

Agent 安装后会作为目标服务器上的服务运行，并监听 TCP `9786`。如果 Agent 无法恢复正常，请检查：

- 目标服务器防火墙和云安全规则允许 Panel 主机访问 `9786/tcp`。
- 目标服务器上的 Docker 正在运行。
- Docker Host 配置正确。
- SSH 账号仍具有所需权限。
- **任务中心**中的操作详情和日志。

如果自动安装因连续失败而停止，请先修正根本问题，再从服务器详情执行安装或重装。

## 5. 部署第一个应用

可以先把 Nginx 容器部署到一台服务器，用于验证完整链路。

打开 **应用 → 应用**，选择 **新增应用**，然后：

1. 将应用名称设为 `hello-nginx`。
2. 启用应用。
3. 将镜像设为 `nginx:alpine`。
4. 网络模式保持 `bridge`。
5. 新增端口映射，将容器端口 `80` 映射到未占用的主机端口，例如 `8081`。
6. 将部署模式设为选择服务器，并选择一台状态正常的服务器。
7. 选择 **保存并应用**。

保存已启用的应用会写入期望状态并启动异步协调，不代表所有目标已经立即部署完成。

打开应用详情，可以查看每台目标服务器的运行状态；在 **任务中心**查看部署阶段和日志。多服务器应用可能在部分服务器成功、部分服务器失败，应检查具体失败目标，而不是认为整个操作会在第一个错误处停止。

实例运行后访问：

```text
http://<目标服务器地址>:8081
```

如果目标服务器启用了防火墙，请在 **安全 → 防火墙** 放行所选主机端口，或者使用反向代理，避免直接公开测试端口。

## 6. 配置实际应用

应用编辑器支持可视化配置和 YAML。常用配置包括：

- 容器镜像和命令。
- CPU、内存、特权模式和 Linux capability。
- 容器环境变量。
- 端口映射和网络模式。
- 宿主机、Docker volume、托管文件和持久化挂载。
- 应用文件和模板。
- 部署到全部正常服务器或指定服务器。
- 反向代理路由。

第一个正式应用建议先只选择一台服务器，确认镜像、文件、端口和运行行为后再扩大范围。使用 Panel 托管持久化挂载的应用只能部署到一台服务器。

后续通过应用详情操作：

- **编辑：**修改期望配置。
- **同步：**让实际运行状态向期望配置收敛。
- **停用：**删除运行中的容器，但保留应用配置和持久化数据。
- **重启：**请求重新执行应用运行周期。
- **删除：**请求清理运行时资源和应用数据，执行前应仔细阅读危险操作确认。

使用运行时日志入口查看容器输出。如果容器启动后立即退出，部署会被标记为失败，不会显示为正常；运行时和任务日志会尽量保留 Docker 或应用返回的原始诊断。

## 7. 配置域名和 HTTPS

Panel 当前通过 Cloudflare 管理 DNS 记录，并使用 ACME DNS-01 验证签发公网证书。

推荐顺序：

1. 在 **设置 → 证书** 填写 ACME 邮箱并检查证书默认设置。
2. 在 **DNS → 域名** 添加 Cloudflare Zone 和 API Token。
3. Token 至少需要目标 Zone 的读取权限和 DNS 记录写入权限。
4. 创建或更新 DNS 记录，使应用域名指向入口网关服务器的公网地址。
5. 在 **证书 → 域名证书** 请求签发证书，并在 **任务中心**跟踪操作。
6. 在 **应用 → 设施应用** 配置反向代理入口节点。这些服务器需要正常的 Agent、Docker，以及可访问的 `80` 和 `443` 端口。
7. 编辑普通应用，为域名、Path 和应用目标端口添加反向代理规则。
8. 保存并应用，然后观察应用和入口网关相关操作直到稳定。

证书签发和入口网关更新都是异步操作。签发失败时，从任务阶段检查服务商认证、DNS 验证传播、授权、清理或最终签发错误。

入口网关每次保存都会检查当前全部域名的 DNS 生效状态：已纳入 **DNS → 域名** 管理且相关服务器填写了 IPv4/IPv6 的域名会异步生成或修正 A/AAAA 记录，已生效且未变化的记录不会被重复写入；网关页面按域名显示“未同步 / 同步中 / 已生效 / 失败 / 跳过”，失败可重试任务后查看。

## 8. 日常操作

### 概览

使用 **概览**查看 CPU、内存、磁盘、网络、运行时间、负载等服务器摘要。指标依赖状态正常且兼容的 Agent。

### 软件包维护

使用 **资源 → 软件包**刷新 APT 更新，并执行选择性升级或全部升级。软件包操作需要正常 Agent 和特权权限，可能持续数分钟。

### 防火墙

使用 **安全 → 防火墙**安装或管理 UFW。启用 UFW 时，Panel 会先保留当前配置的 SSH 端口。对远程服务器应用规则前仍应逐条检查。

### Docker 资源

使用 **资源 → 容器、镜像、网络、卷**查看目标服务器上的 Docker 资源。由 Panel 应用管理的资源通常应从 **应用**修改，因为直接操作 Docker 后，Panel 可能按照应用期望状态重新协调。

### 任务和日志

当操作处于排队、运行、重试或失败状态时，打开 **任务中心**。一次操作可能包含多个任务，尤其是在涉及多台服务器时。打开具体任务可以查看步骤和日志。

## 9. 备份与还原

打开 **设置 → 备份与还原**。

导出步骤：

1. 除非有明确原因，否则保持加密开启。
2. 请求全量导出。
3. Panel 会切换到维护页面。
4. 在维护页登录，按要求提供备份密码并开始导出。
5. 完成后下载归档。
6. 退出维护模式，等待 Panel 恢复正常服务。

还原时，上传已有的 Panel 备份，并完成预检和确认流程。还原会覆盖当前实例数据，不会自动保留旧状态，因此确认还原前应额外创建一份备份。

备份密码和加密归档应分别保存。丢失归档或密码中的任何一个，备份都会失去作用。

## 10. 安全升级

按照[部署文档中的升级说明](deployment.zh-CN.md#升级-panel)操作：

1. 创建新的全量备份。
2. 拉取新镜像。
3. 使用同一个 `panel-data` 数据卷重新创建 Panel 容器。
4. 检查容器状态和日志。
5. 打开 **任务中心**和服务器详情。Panel 版本变化后，系统可能自动安排 Agent 更新，使目标服务器使用匹配版本的 Agent。

## 常见问题

| 现象 | 检查内容 |
| --- | --- |
| 默认账号无法登录 | 使用首次登录时设置的新密码。还原或替换数据卷后，实际使用的账号数据库也会变化。 |
| 新增服务器保存后消失 | 首次 SSH/初始化操作失败。查看任务中心，然后修正地址、端口、凭据、系统版本或特权设置后重新添加。 |
| Agent 不可用 | 确认 Panel 到目标服务器的 `9786/tcp` 连通、目标防火墙、Docker 状态和服务器地址配置。 |
| Docker 状态异常 | 启动目标服务器上的 Docker，并检查 Docker Host；默认通常为 `unix:///var/run/docker.sock`。 |
| 应用部署长期等待或失败 | 打开应用运行目标和任务日志，检查 Agent、镜像仓库、镜像名、端口冲突、文件、挂载和容器输出。 |
| 应用运行但无法访问 | 检查目标主机端口、UFW/云防火墙、DNS 记录和反向代理入口状态。 |
| 证书签发失败 | 检查 Cloudflare Token 权限、Zone 名称、DNS 传播、ACME 邮箱和任务阶段诊断。 |
| 指标或 Docker 资源长时间不更新 | 检查服务器的 Agent 和 Docker 状态，以及 Panel 主机能否维持 Agent 连接。 |
